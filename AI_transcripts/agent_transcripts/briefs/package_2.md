# Work package 2: Corpus and parse

**You own:** `src/triage_app/corpus.py`, `src/triage_app/pipeline/parse.py`, `tests/test_corpus.py`, `tests/test_parse.py`. Both files exist as typed stubs; replace them.

**SPEC sections:** "Corpus: two test days of 300 emails, plus a tuning set" (file format, the loader, the normalization table, tuning set), "Stage files", "How to construct it" (parsed body is the text of record).

**Build:**
1. `corpus.py`: `load(path) -> tuple[list[Email], list[EmailLabel]]` doing the loader's five steps in order. The real corpus rows have 14 fields and **no `received_at` and no `redundant_of`** — assign `received_at` in file order, spread evenly across the set's trading window (`config.SET_DATES`, `config.SET_WINDOW`, `config.SET_TZ_OFFSET`; for the fixtures use the day_1 date). Generation fields (`email_type`, `systemic`, `angle`, `day`) are dropped — they never reach `Email`. `human_attention` inside `additional_labels` sets the flag. Implement every row of the normalization table, each with its own test. Collect rows that fail validation or need hand fixing and list them in the report. Add the distribution report (label counts vs targets, the checks the spec assigns to the loader: human_attention count, macro/sector/government count, thesis_relevant per ticker). Add `split_tuning(emails, labels, seed=...)` → fit/validation, two-thirds/one-third stratified by triage label with a fixed seed, and `check_separation(tuning, test_sets)` by subject+body hash. CLI: `uv run python -m triage_app.corpus --set day_1` (choices `config.CORPUS_SETS`; a missing tuning file prints a clear "pending" message, exit 0).
2. `pipeline/parse.py`: `run(in_dir, out_dir, ctx)` loads `in_dir/emails.jsonl` with the loader and writes `raw.json` (Email, raw body) and `parsed.json` (Email, cleaned body). `process(email) -> Email` cleans the body conservatively: normalize line endings to `\n`, remove zero-width and non-breaking-space characters (NBSP → space), strip trailing spaces on lines, collapse 3+ blank lines to 2, strip the ends. Do not paraphrase or drop content — every later quote is checked against this text. Wrap each email in `ctx.recorder.stage("parse", email_id)`.

**Done when:** the fixtures load, split and normalize, and the report prints; each normalization row has a test; parse output validates. Then (no model calls involved) run `uv run python -m triage_app.corpus --set day_1` and `--set day_2` and include both reports in your final message, plus `uv run python -m triage_app.pipeline.run --set day_1 --stage parse` writing `data/out/day_1/raw.json` and `parsed.json`.
