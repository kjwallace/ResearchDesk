# Work package 7: State and app

**You own:** `src/triage_app/state/apply.py` (new), `src/triage_app/pipeline/deliver.py`, everything under `src/triage_app/web/` (`main.py`, `templates/`, `static/`, any `web/*.py` helpers), and tests `tests/test_apply.py`, `tests/test_deliver.py`, `tests/test_web.py`.

**SPEC sections:** "State: model, thesis and change log", "Labels and suggestions" (all subsections), "Screens", "Routes", "Data contracts", "Stage files", "Starting values", "Monitoring: token use and latency" (the Monitor screen and the Live trace), "Stack and repo layout" (live-route protections and presets), design rules 5–7 and "Guardrails".

**Build:**
1. `state/apply.py`: turn analyst actions into `LogEntry`s — accept existing-thesis (pillar_evidence), accept new thesis (pillar_added with `fold.next_pillar_id`), update a linked assumption (driver_updated, before/after filled by code), set conviction (conviction_changed), undo (a reversing entry), dismiss (status only). Raise a `ConvictionReview` when `fold.net_contradicting` reaches `config.CONVICTION_REVIEW_STRENGTH`. Pure functions over (seed, log).
2. `pipeline/deliver.py`: `process(out_dir, ctx) -> Brief` assembles `brief.json` deterministically per "Where each email appears" and "Order and alerts" (alerts budget `config.ALERTS_PER_DAY`; attention alerts at `config.ALERT_ATTENTION`; wrong-if alerts on positions ≥ `config.ALERT_WRONG_IF_MIN_BPS`); every email appears exactly once across the lists (needs_attention may also list an email shown elsewhere — follow the spec table). `run` writes `brief.json`.
3. `web/`: FastAPI + Jinja + HTMX (load htmx from a pinned CDN URL), server-rendered, no JS build. Every route in the "Routes" table plus **`GET /monitor`** (tokens and latency for the set's latest `metrics.json`: per stage, per model, per email p50/p95, spent vs uncached; link to the slowest/costliest emails) — note the spec's Monitor screen. Read stage files from `TRIAGE_DATA_DIR` (default `data/out/day_1`; tests point it at `tests/fixtures/out`). Session state (change log, suggestion statuses, conviction reviews, live-run counter) in server memory keyed by a signed session cookie; `/reset` restores the seed, `/undo` reverses. Every page shows a visible "synthetic data" banner. Quarantined emails show sender and subject only, everywhere. The email view highlights quoted sections in the parsed body. The Suggestion page shows a stated figure beside the book value and consensus and the EPS/target-price effect via `state.compute.project`. Verify (`POST /suggestion/{id}/verify`) and Live (`/live`) and "this mattered" call into other packages' functions (`modules.verify_agent.verify`, the stage `process` functions) — import them lazily and render a clear "not available yet" fragment if they raise `NotImplementedError`, so routes answer before those packages land. Live route: 10,000-char cap (`config.LIVE_INPUT_CAP_CHARS`), `config.LIVE_RUNS_PER_HOUR` per session, presets from `data/live_presets/` (may be empty for now), a stage-by-stage trace with tokens and latency per stage from a fresh `Recorder`. Eval page reads `eval.json`; the three hand reviews show as pending when empty. Criteria page shows each `criteria/*.md` as written plus `data/out/criteria_history.json` if present.

**Tests (fixtures, FastAPI TestClient):** build step 5 on the fixtures — accepting a thesis suggestion logs the evidence; updating a linked assumption changes EPS on the page; reset restores the seed; undo. Every route under "Routes" plus `/monitor` answers 200 (or the right HTMX fragment) with fakes standing in for other packages' modules. Brief items plus audit items plus quarantined account for every fixture email exactly once. Quarantined bodies never appear in any HTML response. Every page contains the synthetic banner.

**Done when** the above passes. `uv run uvicorn triage_app.web.main:app` serves the fixtures with `TRIAGE_DATA_DIR=tests/fixtures/out`.
