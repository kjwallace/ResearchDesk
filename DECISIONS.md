# Decisions

Choices made where `SPEC.md` was silent, contradicted itself, or was changed by the person running the build. Newest last.

| # | Decision | Why |
|---|----------|-----|
| 1 | The earlier "finresearch" prototype (README, pyproject, uv.lock, .env.example, main.py, `data/skills/`) is archived in `legacy/finresearch/`, not deleted. | It conflicted with the spec. The files had no git history, so archiving keeps them recoverable. |
| 2 | Python 3.14. | Person's instruction. Every pinned dependency installs on 3.14. |
| 3 | Corpus sets are `day_1`, `day_2` (test) and `tuning`, named after their folders. Each set is run separately into `data/out/<set>/`. | The corpus folders were renamed. The repeat check is same-day only, so days must run apart. |
| 4 | Redundancy thresholds are fixed at 0.85 / 0.75 / 0.6 and not swept. The eval reports `repeat_flagged` and `repeat_precision` only. | The corpus has no `redundant_of` labels (person's instruction: compute redundancy at run time only). The spec gave the subject threshold as both 0.7 and 0.6, so it is unified at 0.6, the "Starting values" table. |
| 5 | The tuning split is two-thirds fit, one-third validate. | The tuning set is planned at 100 emails, not the 150 the spec first assumed. It is generated outside the build. |
| 6 | **All generative model calls go through OpenRouter**, via `triage_app/llm.py` (`OpenRouterClient`). The Anthropic API is never called directly. | Person's instruction. The Anthropic account also had no credit when the build started. |
| 7 | **Model IDs come only from `.env`** (`JEV_MODEL`, `ANALYSIS_MODEL`, `NOTES_MODEL`, `EMBEDDING_MODEL`). `config.py` resolves each on first use and raises `MissingModelError` when one is unset. | Person's instruction. Values set: `jev-1.13.0`, `anthropic/claude-sonnet-5.5`, `anthropic/claude-haiku-4.5`, `BAAI/bge-small-en-v1.5`. |
| 8 | **Embeddings use a Hugging Face model**, pulled with `huggingface-hub` and run locally with `sentence-transformers` (`triage_app/embed.py`), instead of fastembed. | Person's instruction. Any HF repo ID in `EMBEDDING_MODEL` works. bge-small gives 384 dimensions and a 512-token input limit. |
| 9 | **Stage 3 uses the TypeSafe SDK route** (`TypeSafeClient.system_one`). A code sweep fits every threshold; ReAnchor is not used. | The step 0 spike sent one `day_1` email through both routes. Both worked: the SDK returned 14 answers from `jev-1.13.0` in about 0.3 s with 1,306 input / 349 output tokens reported. In DSPy, criteria are baked into the `Noul[...]`/`Choice[...]` types at class creation, not set on predictor fields, so the spec's condition for the DSPy route is not met as written. Rebuilding the signature per criteria version does work, but it double-caches against `data/cache/` and gives ReAnchor's caching no stable program. The SDK maps one-to-one onto the criteria files and reports token usage directly for monitoring. |
| 10 | A Noul question's criteria are sent as `{"true": <file text>}`, with the "no" side undescribed. | SDK 0.7.2 takes Noul criteria as a `{true, false}` pair, not one text. The criteria files describe what counts as yes. |
| 11 | `JEV_MODEL` is pinned to `jev-1.13.0`, the version the spike returned for `jev-latest`. | The spec asks for a numbered pin before the final eval. |
| 12 | One path for every model call: `monitoring.cached_call` (disk cache + token/latency record). DSPy's own cache is off. DSPy modules bind `modules/lm.RouterLM`, which routes through the OpenRouter client. | One cache keyed as the spec says, and monitoring that sees every call. `RouterLM` uses `BaseLM.forward`, which DSPy 3.4 deprecates but supports; DSPy is pinned to 3.4.0. |
| 13 | `numpy` is imported before `dspy` wherever both are used. | On Python 3.14, DSPy's lazy importer breaks a later first import of numpy (`data type 'bool' not understood`). |
| 14 | The modeled fiscal year is the latest reported year + 1 (NVDA FY2027, MSFT FY2027, AMZN FY2026, AAPL FY2026, GOOGL FY2026). `seed_merge` derives it from the filings and overrides the book draft's labels. | `compute` applies one year of growth to the 10-K base. The draft's FY2027 for AMZN, AAPL and GOOGL would have skipped a year. |
| 15 | NVDA's revenue lines come from its revenue-by-market-platform table (Data Center, Gaming, and the sum of ProViz + Automotive + OEM). GOOGL's lines exclude hedging losses ($0.127B), so they sum $0.127B above total revenue. | The spec's drivers follow these lines rather than reportable segments. Details are in `data/seed/base_figures.json` notes. |
| 16 | Generation prompts 01 and 02 were run in fresh Claude Code subagents (Claude Opus 5.5), each given only the text below the prompt's line. Prompts 04–06 run through OpenRouter with `scripts/run_generation_prompt.py`. | The Anthropic API refused the first runs (no credit). The spec allows a fresh subagent. The OpenRouter switch came after. |
| 17 | Stage `run(in_dir, out_dir, ctx)` takes a third argument, a `RunContext` with the clients (lazily built; fakes in tests), the recorder, cache, criteria and thresholds. `in_dir` is the corpus folder for parse and the set's out dir for every other stage. | The spec's `run(in_dir, out_dir)` gives modules nowhere to receive their clients. |
| 18 | The 10-K text is saved to `data/filings/<TICKER>_10-K.txt` from the latest filing as of 2026-10-08 (AAPL's FY2026 10-K was not yet filed, so FY2025). | For the verify agent's filing search. |
| 19 | Quarantine when **either** safety probability (`instructs_ai` or `possible_mnpi`) reaches 0.40. | Stage 4 step 1 names only the injection question, but the labels table says "Jev's two safety questions" and the guardrails quarantine possible inside information. |
| 20 | Brief accounting: every email sits exactly once across the suggestion lists, `relevant_unlinked`, `audit` and `quarantined`; `needs_attention` is an extra layer that may repeat an email placed elsewhere. | "Where each email appears": attention emails show "whatever else applies to it". |
| 21 | Gate reason wording: `thesis_relevant 0.71; signal score 0.92 clears 0.60`, `irrelevant 0.81; signal score 0.04 is below 0.60`, `quarantined: instructs_ai 0.97 reaches 0.40`, and for a check relabel `redundant: repeat of <id> (content 0.96, subject 0.86); jev monitor 0.42; signal score 0.52 is below 0.60`. | Set by the fixtures; stage 4 follows them. |
| 22 | Email-kind option keys are snake_case (`company_release`), matching `config.EMAIL_KINDS`; the generated wording file was edited to match. | The generated draft used "company release" with a space. |
| 23 | The claim-ID pattern in `tools/analysis_agent.json` is loosened from `^synthetic_\d{6}\.c\d+$` to `^[A-Za-z0-9_-]+\.c\d+$`. | The original rejects fixture and live-route email IDs. |
| 24 | The `triage` question's wording was edited to say judge content, not sender or presentation. | The generated wording named `sender` and `subject`, against "Jev judges content, not presentation". |
| 25 | The generated skill files were renamed to `skills/alter_existing_thesis.md` and `skills/spawn_new_thesis.md`. | Prompt 04's body never names its output paths; the README and spec do. |
