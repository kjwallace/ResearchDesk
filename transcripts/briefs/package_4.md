**Build:**
1. `modules/classify.py`: build the 14 questions from the criteria set (`criteria.criteria_text(criteria, label)`) and the wording in `instructions/jev_questions.md` (package 1 is generating it now; parse it defensively by question ID — triage, human_attention, affects_<TICKER> ×5, topic_macro/sector/government/other, kind, possible_mnpi, instructs_ai — and fall back to short stub wording for any ID not found, logging which). The kind and two safety questions have fixed wording and no criteria file. `affected_tickers.md` supplies criteria for all five company questions; the wording names the company. State sent = exactly `{"sender","sender_email","subject","body"}` from the parsed email — nothing else. Trimming: if body + longest question > `config.JEV_INPUT_LIMIT_TOKENS` (count `config.CHARS_PER_TOKEN` chars per token), keep the start of the body and set `truncated`. One `system_one` call per email, all 14 questions, through `monitoring.cached_call(namespace="jev", model=config.JEV_MODEL, payload={state, questions as JSON}, criteria_version=criteria.version, usage=lambda r: (r.usage.input_tokens, r.usage.output_tokens), ...)` with a dump/load that round-trips the answers you need. Return a `TriageRecord` with all 14 answers.
2. `pipeline/classify.py`: `run` reads `parsed.json`, writes `triage.json`, per-email `ctx.recorder.stage("classify", email_id)`. Use `ctx.jev` and `ctx.criteria`.
3. `pipeline/gate.py`: `process(triage, redundancy, thresholds) -> EmailResult` applying the five ordered steps and the four result cases exactly (quarantine when either safety probability ≥ `config.QUARANTINE`; redundancy-check relabel only when flagged and signal score < pass threshold; pass when signal ≥ pass threshold or truncated). The one-line reason composed by code, e.g. `low_value 0.62; signal score 0.11 is below 0.60` / `signal score 0.81 clears 0.60` / `truncated; passed on the first chunk` / `quarantined: instructs_ai 0.71 ≥ 0.40`. `run` reads `triage.json` + `redundancy.json`, writes `results.json`, thresholds from `ctx.thresholds`.

**Tests:** with `FakeJev`, every fixture email gets one result; each gate case under "Classification with Jev" has a test (quarantine either question, label argmax, redundancy relabel vs passing repeat, tickers/topics thresholds, attention, gate pass/stop/truncated, the four result cases); a test proves the Jev request holds only the email's four fields and the criteria/wording (no book, no redundancy, no other email, no label); truncation test.

**Done when** the above passes. You may run the classify module live on the ten fixture emails once (through the cache) to confirm the real SDK path end to end; report latency and tokens. Do not run a full corpus set.
