# Work package 8: Evals and tuning

**You own:** everything under `src/triage_app/evals/` (`metric.py`, `score.py`, `tune.py`, `criteria_check.py`) and tests `tests/test_metric.py`, `tests/test_score.py`, `tests/test_tune.py`, `tests/test_criteria_check.py`.

**SPEC sections:** "Evaluation and guardrails" (the measures table and review-sheet rules), "Tuning", "Starting values", "Relevance criteria" (steps 4–5 and the keep rule), "Stage files", "Data contracts" (`EvalReport`, `Miss`, `Thresholds`, `LabelChange`, `CriteriaHistoryEntry`). Note the corpus has **no `redundant_of`**: report `repeat_flagged` (count) and `repeat_precision` (share of flagged emails the corpus labels redundant) only; redundancy thresholds are fixed and never written by tuning.

**Build:**
1. `metric.py`: pure functions for every measure key in the table (gate_recall, monitor_gate_recall, gate_reduction, signal_accuracy, triage_accuracy + confusion, ticker_f1, attention_precision/recall, topic_f1, repeat_flagged, repeat_precision, stray_suggestions, quote_faithfulness over notes and suggestions, meetings_share from Jev's email kind, and the three review keys from the filled sheets). A quarantined email counts as a miss on every label measure.
2. `score.py`: `uv run python -m triage_app.evals.score --set day_1` loads labels with the corpus loader (`triage_app.corpus.load`, package 2 — until it lands, read `tests/fixtures/labels.jsonl` directly for tests), reads the set's stage files, writes `data/out/<set>/eval.json` (`EvalReport`, corpus = the set) with misses listed, and writes the two review sheets (`review_notes.csv`, `review_suggestions.csv`: one row per item, ID, kind, a yes/no column per check, comment) unless filled ones exist; reads filled sheets for the review keys.
3. `tune.py`: `uv run python -m triage_app.evals.tune` fits on the tuning set's fit split (needs `data/corpus/tuning/emails.jsonl` and `data/out/tuning/` stage files; when missing, print "tuning pending: tuning set not available" and exit 0): pass threshold = highest value that passes every thesis_relevant and ≥95% of monitor emails; attention, ticker and topic thresholds by best F1 (code sweep — ReAnchor is not used, DECISIONS #9). Writes `tuned/thresholds.json` with the redundancy thresholds copied from config unchanged.
4. `criteria_check.py`: `uv run python -m triage_app.evals.criteria_check` reruns stage 3 (`pipeline.classify` with `ctx.jev`) and stage 4 on the tuning set with the current criteria files, refits thresholds in memory (never writes them), prints before/after scores per label on fit and validation, lists emails whose label changed, and appends a `CriteriaHistoryEntry` to `data/out/criteria_history.json` ("before" = the previous entry). Pending message when the tuning set is missing. Only this package and the loader read labels.

**Tests (fixtures; FakeJev; no network):** each metric on hand-built cases including the quarantine-as-miss rule; score writes a valid `eval.json` and both sheets from `tests/fixtures/out` + `labels.jsonl`; tune picks the right thresholds on a synthetic case and writes valid `thresholds.json`; criteria_check runs on a tiny synthetic tuning set with FakeJev, writes a valid history entry, and reports a label change after a criteria edit (use a temp criteria dir).

**Done when** the eval, tuning and criteria-check commands run on the fixtures with a fake classifier and write valid files.
